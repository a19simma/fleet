# fleet-server traps

- **Migration numbers.** Check `ls crates/fleet-server/migrations` for the next free number before naming a file. A task title can name a number that is taken, and sqlx refuses duplicate versions.
- **Shared column list.** `job_columns!()` in `store.rs` is a macro because `concat!` cannot take a `const`. Use the macro in each job `SELECT` and keep each statement a literal.
- **Dynamic SQL.** sqlx 0.9 `query` takes only `&'static str`. `format!` into a query fails with E0277. Write each statement as a full `const` literal.
- **Job ids and idempotency.** `job_id` is `EventId::generate()` (ULID shape), generated in Rust and bound as a parameter. A repeat `submit_job` with the same key and identical prompt, repo, base ref and `open_pr` returns the stored job. Different parameters give `StoreError::KeyConflict`, which the handler maps to gRPC `ALREADY_EXISTS` with a fixed message.
- **Reaper tests.** Postgres and tokio paused time do not mix. `expired_lease_becomes_lost` uses a 1 s lease, a 100 ms reaper period, real time, a `Notify` the reaper signals, and a 5 s `timeout`. Never `sleep`.
- **Web markup changes the generated sheet.** After any change under `crates/fleet-server/src/web`, run `mise run css:check`; when it reports stale, run `mise run css` and commit `assets/ui.css`. New class use changes the sheet even if no CSS file was touched.
- **Box names in tests.** Use names like `alpha` wherever the validator is not under test. The validator only accepts `box-<digits>`, but verify.sh's private-pattern grep rejects that literal in source, so a test that needs a valid name builds it at runtime from a variable, as `format!("box-{n}")`. A worker's green verify missed a `box-N` literal added in a late edit: rerun verify after the last edit.
- **Retention tests.** Age rows with a direct `UPDATE`/`INSERT` of `finished_at` and `created_at` and call `run_retention_once` with `Policy::default()` plus `with_batches`; `Policy::new` is fallible and its fields are private, so a test cannot build an invalid pair; never sleep. The prune statements are full `const` literals bound with `$1` days and `$2` limit.
- **Test timestamps come from the DB clock.** Read them through the pool (`SELECT clock_timestamp()`), never `SystemTime`: mixing host and Postgres clocks made `pre_reboot_event_after_new_boot_heartbeat_keeps_boot_id` flake.
- **Wide row asserts.** Tuples above 12 fields lack `Debug` and trip `clippy::type_complexity`. Read wide rows in tests as `SELECT (to_jsonb(t) - 'job_id')::text` and compare with `serde_json::json!`.
- **Job owner default.** `jobs.user_id` is NOT NULL with `DEFAULT bootstrap_user_id()` (migration 0018). Every production insert (`store.rs`, `batches.rs`, `store/ci_retry.rs`) binds `user_id` and `agent`; only a raw `INSERT INTO jobs` in a test falls back to the default and lands on the `bootstrap` user, which the function creates on first use.
- **Migration backfill tests.** Use `#[sqlx::test(migrations = false)]`, run a `Migrator` filtered to versions below the new one, insert old-shape rows, then run the full `sqlx::migrate!`.
- **Recovery and reset tasks.** Enumerate every credential class of the user (passkeys, sessions, api tokens, setup codes) and test that each is revoked.
- **A new RPC or service in `fleet.proto` needs a classification.** Add the RPC to `CLASSIFIED` in `tests/owner_reads.rs` and to the ADR-0042 table, then run `cargo nextest run -p fleet-server --test owner_reads`. `every_rpc_in_the_proto_is_classified` enumerates the proto, and FGJ-3 went red on it after a service add.

## Catalog, capabilities and admin

- **Admin RPCs sit outside both static token scopes.** `auth.rs` lets `FleetCatalogAdmin` (`UpsertCatalogItem`, `SetCatalogItemEnabled`) and `FleetCapabilityAdmin` (`GrantCapability`, `RevokeCapability`, `ListCapabilities`) and the four admin `FleetHosts` RPCs (`RemoveHost`, `ApproveHostPrivate`, `RevokeHostPrivate`, `ListHostRequests`) through only for a per-user API token whose user has `users.is_admin`. The box token, `FLEET_CLIENT_TOKEN` and a non-admin token get `PERMISSION_DENIED`. `FleetCatalog.ListCatalog` passes the client scope, then the handler calls `admin_of` and answers `PERMISSION_DENIED` with `admin required` to any caller that is not an admin user, so the static client token gets it too. It lists every item, admin-disabled ones included, like the web catalog page.
- **Admin writes lock the actor row.** `catalog::upsert_item`, `catalog::set_enabled` and the `Capabilities` store read `is_admin` with `FOR SHARE` on the acting user in the write transaction, so a demotion in flight blocks or refuses the write. A new admin write path takes the same lock and does not trust the `Caller` flag read at authentication.
- **A catalog item keeps its kind and name.** `upsert_item` validates through `fleet_core::catalog::CatalogItem::new`, stores the digest of the validated content and never touches `admin_enabled`. A changed kind or name for an existing id is `FAILED_PRECONDITION` and a second id with the same kind and name is `ALREADY_EXISTS`.
- **Capabilities are `profile:tools`, `forge:github_app` and `env:scripts`.** `cred::capability::PROFILE_TOOLS` and `FORGE_GITHUB_APP` are the names, and the table CHECK (migration 0026, widened by 0034 and 0039) lists all three. A new capability needs a `Capability::ALL` entry, a migration that widens the CHECK, a constant and an entry in `cred::capability::KNOWN`. `fleet-proto/tests/capability_contract.rs` compares the latest CHECK list to `Capability::ALL`; the admin page lists every entry of `ALL`, so `web_catalog` grants each one and fails with a 400 while `KNOWN` lacks it.
- **`CreateProfile` with `edit` set never creates.** `Store::edit_profile_content` (`profiles::edit_owned`) saves a version only when the caller already owns the name. Someone else's shared profile is `PERMISSION_DENIED` (`only the owner can change this profile`), a private foreign or unknown name is `NOT_FOUND`, and nothing is written. `fleet profile item` and `prompt` set `edit`, so the CLI no longer forks a shared profile under the caller's name; the web selection post refuses through `update_owned`.
- **Revoke of an unknown user is `NOT_FOUND`.** `Capabilities::revoke` takes `FOR SHARE` on the target row and answers `no such user`, as grant and list do, so the CLI and the web page give one answer.
- **Admin pages repeat the gate.** `web/catalog.rs` and `web/capabilities.rs` start every route, GET and POST, with an admin gate that reads `users.is_admin` per request, and every POST checks the session CSRF token.
- **`fleet-server admin` is the recovery path.** `cred/admin.rs` runs user create, passkey reset, admin grant and admin revoke by direct database access, each in one transaction with an `admin_audit` row.

## Model allowlist

- **`FLEET_MODEL_ALLOWLIST` is a comma-separated list of exact model ids.** `config.rs` parses it with `ModelAllowlist::parse`; nothing is trimmed and a bad list stops startup without echoing the value. Unset means every model passes.
- **It is checked at profile create, update, submit, batch pin and blob serve.** `profiles::create_owned`, `profiles::update_owned`, `profiles::pin_for_submit` (reached from `store.rs`), `profiles::blob_for_lease` and `batches::pin_profiles` (through `profiles::require_model`) return `StoreError::ModelDenied`, which `service.rs` maps to `PERMISSION_DENIED`. A profile with no model passes. fleetd checks again with its own `model_allowlist`.

## Timing

- **`ReportTiming` is checked before any row is written.** `timing::store_timing` refuses with fixed reasons (`REASON_PARTS_SUM`, `REASON_SPAN_OUTSIDE`, `REASON_WINDOW_AHEAD`, `REASON_AGENT_WINDOW`, `REASON_SUMMARY_MISMATCH`), allows `WINDOW_TOLERANCE_MS` (30 s) of clock skew and needs a running lease that matches box, job and attempt. Spans are capped at `fleet_proto::MAX_SPANS` and shell commands at `MAX_SHELL_COMMANDS`.
- **Shell logs are capped per job.** `report_shell_log` stores at most `MAX_LOG_COMMANDS_PER_JOB` commands and `MAX_LOG_BYTES_PER_JOB` (4 MiB) of chunks. `StreamShellLog` polls every `STREAM_POLL` and ends after `STREAM_MAX_WAIT` (600 s); the client reconnects with `from_seq`.
- **`GetJobTiming` refuses an oversize reply.** `MAX_JOB_TIMING_REPLY_BYTES` derives from the stored caps, and `with_timing_reply_cap` shrinks it so a test can cross it.
- **Timing pages scope by owner.** `web/timing.rs` serves `/jobs/{job_id}/timing` and `/jobs/{job_id}/shell/{command_id}/log`, and answers 404 for a job that is unknown or not the session user's.
- **Work claim.** `claim_work` locks `work_project` FOR UPDATE, checks ready, inserts every slice lease in one transaction and refuses a held slice with `slice is leased`. Evidence is redacted before it is cut to `MAX_EVIDENCE_BYTES`. `routes` wires `BearerAuth::redactor`, so the box token, the client token and the installation-token shape are masked in stored evidence.

## Work project repo

`work_project.repo_id` is a composite foreign key `(user_id, repo_id)` to `user_repos (user_id, id)`, `ON DELETE SET NULL (repo_id)` (migration 0041), so the schema refuses another owner's row and a registry delete clears the binding. `create_work_project` and `set_work_project_repo` take `FOR SHARE` on the registry row after the project lock. A registry delete takes the registry row first and then updates the referencing project, so a delete racing a set can deadlock; Postgres aborts one side with `40P01`.

## Edit rpcs

`FleetEdit` lives in `store/work/edit.rs`. Every call locks the `work_project` row before any read, so `base_hash` is recomputed against the committed graph. `DecideEdit` takes only a per-user API token: keep the `FleetEdit` prefix out of the plain Client scope check for that path (`auth::DECIDE_EDIT`), and the store refuses the Bootstrap user too. Accept applies a `slice_op` or `pitfall` in the decide transaction through `replace_slices` and the graph `check`, and a failure answers `REASON_DOES_NOT_APPLY` and leaves the edit pending. `base_hash` is server computed for `slice_op` and `pitfall` and supplied by the filer for `file_patch`, which never goes stale and is never applied. The pending cap and payload bound are `fleet_proto::MAX_PENDING_EDITS_PER_PROJECT` and `MAX_EDIT_PAYLOAD_BYTES`.

`FleetBoxTokens` (ADR-0069) joins the Client scope and refuses the static Client token with `BOX_TOKENS_NEED_USER_TOKEN`. An `fbx_` token resolves to `Scope::Box` and a `BoxCaller` extension, never a `Caller`; every Box-scope handler calls `bound_box` first. A partial unique index cannot use `now()`, so `issue_box_token` closes the name's expired tokens in the issue transaction. `box_token_audit` is insert-only by trigger, and every write to it shares the transaction of the change it records. A judge job takes its target's `user_id`, so a user's Box is not starved by a judge submitted with the static Client token. Every lease-bound worker RPC (profile blob, transcript, credentials, environment, report job, timing and shell log) calls `FleetService::owned_by_token` before the store, because the lease predicates key on job, attempt and box only and a re-issued Box name would otherwise reach another user's job; a new lease-bound RPC needs the same call and a case in `tests/box_token_lease_owner.rs`. `ReportShellLog` ignores the client `box` field for static tokens (a test pins it) and checks the lease holder only for a bound token.

`FleetEnvironments` (ADR-0067) joins the Client scope but refuses the static Client token on every method with `ERR_ENV_NEEDS_USER_TOKEN`, by path prefix in `auth.rs`, because the token maps to the Bootstrap user. Handlers in `environments.rs` parse every input into the `fleet-core` types before any lookup, then resolve the name through `EnvironmentStore::resolve_environment`, which is scoped by user: a foreign name gives exactly the `ERR_ENV_NOT_FOUND` of an unknown one. `save_version` reads the `env:scripts` grant row `FOR SHARE` after the Environment `FOR UPDATE` whenever the spec holds a script, in the transaction that writes the version.

Submit and batch pins follow ADR-0067 decisions 10 and 11. `environments::resolve_pin_with_defaults` takes the repository binding, then the Profile binding, then none, and a binding to an Environment that needs a revoked `env:scripts` refuses and never falls through. A batch with a named Environment pins every child alike, and a batch with none resolves each child's default (`batches.rs` `resolve_batch_pins`). A CI retry inherits through `environments::pin_inheritable`, not `resolve_pin`. A replay under one idempotency key compares through `pin_matches` (named) or `default_pin_matches` (`store.rs`), so editing or deleting an Environment between two submits is a `KeyConflict`.

## Retro rpcs

`FleetRetro` lives in `store/work/{retro,pitfall,brief}.rs`. Filing an improvement locks the `work_project` row, then bumps `occurrences` and inserts the occurrence row in one transaction. `CloseRetro` is refused while an improvement of the retro has no disposition. A pitfall with no project is user-level and scoped to its owner. `GetWorkBrief` ranks pitfalls before improvements and caps the text at `BRIEF_TOKEN_BUDGET` tokens of `BYTES_PER_TOKEN` bytes.

## Git remotes page

`/hosts` lists hosts, adds through `HostService`, removes for admins only (`admin_post_gate`), and shows pending private requests and approved addresses to admins only. `Web::with_hosts` injects the service for tests. The registered-repositories table is `repos::repo_table`, shared with `/repos`. `/hosts/approve` and `/hosts/revoke` call `HostService::approve` and `revoke`, as the RPCs do. They use their own `admin_or_missing` gate, not `admin_post_gate`: a non-admin gets 404 (the remove route still gives 403), and the approve form posts back the addresses of the pending request so the service accepts only what it resolves now. The page has no deny button: a pending request stays listed until an admin approves it.

`GetJobCredentials` (`cred::store::release_for_job`, `job_host`) reads `git_hosts` live under `FOR SHARE`, so an approve or revoke in flight waits. A host with no row, a `github` row for any host but `github.com`, and a Forgejo host without `allow_private` whose registered repository for the Job owner has the epoch `verified_at` (a revoke) all fail with `PRECONDITION_HOST_NO_CREDENTIAL` before any credential is opened. A repository that does not parse, and is not a `file://` or absolute path with `with_file_repos` on, is refused the same way before any App mint, so it writes no `github_app_mint` row. A Forgejo host with no registered repository row is not detected as revoked: its PAT still releases with `allow_private` false and no approved addresses. The reply has one `hosts` entry: `github.com` repeats the forge credential, a Forgejo host carries only the `forgejo_pat`.
