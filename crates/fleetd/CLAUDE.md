# fleetd

## Spawn tests

- **Fake agent or git script.** Write it once in a `OnceLock<TempDir>` before any test spawns, so no thread forks while the file is open for write (Linux `ETXTBSY`). One script serves every test: the prompt carries `mode:path`.
- **Start races.** A freshly written script can take over 100 ms to start on macOS, so a report heartbeat proves nothing about the child. Gate a kill on a signal from the child: a fifo the child's descendant opens, read by a test task that sends on a oneshot once its `open` returns. Reading the same fifo to EOF proves the whole process group died.
- **Lease heartbeat.** The runner reports at least every 30 s. Tests shrink `report_interval` and `flush_interval`.
- **Escaped descendants (`setsid` test only).** A `setsid` descendant must finish `setsid` before the agent script exits, because the exit kills the process group. The script waits for the pid file the descendant writes, and the test kills that pid.
- **Surviving descendants can hang the test binary.** A red kill test leaves `sleep 300` holding the runner fifo. The test `Reader` avoids the blocking `tokio::fs` fifo `open`, but a blocking-pool read of a pid fifo can still stall the runtime drop. Kill leftovers by pid, never by name pattern.

## Runner loop

- **List every exit arm of a loop with several, and test each one for the heartbeat and the group kill.** The arms are stdout EOF, child exit, deadline, shutdown and report error. A past task failed twice because each retry fixed the named arm and left a sibling: group disarmed after wait, report awaited inside `select`, no heartbeat arm after stdout EOF.
- **A change to the spawn path, or to a default that changes what a job does after the agent exits, needs every test binary that spawns the fake agent.** `grep -l 'claude_bin\|fake_gh\|"gh"' crates/fleetd/tests/*.rs` lists them, and `daemon_jobs` and `e2e_jobs` are among them. One change ran only `telemetry` and `runner::` tests, and another added a 900 s CI wait after the PR that a fake `gh` answering every call alike turned into four red integration tests; both went red only in the independent verify.

## Profile jobs

- **`Reporter::profile_blob` defaults to `UNIMPLEMENTED`.** A test reporter that omits it makes any Job with a `profile` fail closed with `profile invalid: profile could not be fetched`. A test that needs a blob implements it, as `Served` in `runner.rs` and `Blob` in `jobs.rs` do.
- **The `GetProfileBlobReply.catalog` bundle is applied as sent.** `load_profile` also resolves the Profile selection for the job's runner, only to queue the Kimi dropped-subagent notes (`AgentRunner::queue_dropped_notes`, `dropped_subagent_events`, `fleet_core::catalog::resolve`); that result never changes the bundle. `load_stamped` drops items that are not `admin_enabled` or that the Profile selection names, refuses the snapshot when it exceeds `MAX_BLOB_CATALOG_ITEMS` items or `MAX_BLOB_CATALOG_BYTES` content bytes (`CatalogTooLarge`), repeats an id (`CatalogDuplicate`), carries an item digest that differs from the digest of its fields (`CatalogDigest`), or holds an item the core rules refuse (`CatalogName`, `CatalogBody`, else `Catalog`), and writes skills to `skills/<name>/SKILL.md`, subagents to `agents/<name>.md` and context items to `.claude/ctx/<name>.md`. A catalog tool needs the tools stamp. Only the claude runner reads the bundle; codex and kimi take the tool pins and the prompt only. The subagent frontmatter check is a strict allowlist, not a scan: `---\n`, then only `name|description|color|tools: <one-line printable-ASCII plain scalar>` lines (no repeat, no indent, no CR or tab), then `---\n`, with `tools` names checked against the Floor deny set and `model` refused, since only the Profile model is checked against the box allowlist; anything else is refused, as is a BOM or a leading `---` that is not that fence.
- **A new `FleetWorker` stub needs `get_profile_blob`.** `daemon_jobs` serves a real blob through `Worker::blob`; the other stubs return `unimplemented`.

## Timing capture

- **The OTLP receiver is systemd-launcher only.** `otel::OtelReceiver::bind` listens on `otel.sock` in the job directory and accepts `POST /v1/logs` with a per-job bearer token and a JSON body. `select_launcher` attaches it through `with_telemetry` after `require_host_netns()` succeeds; on a refusal it logs a warning and the launcher runs with no capture. The direct launcher never starts one. `AgentSpec.otel` is `!judge` for claude and `false` for the codex and kimi specs, so only a claude job that is not a judge job gets a receiver.
- **Capture never fails a job.** `runner::timing::Capture` drains the receiver bodies, stamps each with its arrival time on the job clock, parses it with `otel_parse::parse_logs` and maps the events to spans. A failure becomes a `Note` with fixed text that finish pushes to the transcript, and `ReportTiming` goes out with what exists. The drain waits `QUIET_PERIOD` (1.5 s) for the stream to go quiet and never longer than `MAX_FLUSH_DEADLINE` (10 s).
- **Background shell time comes from pueue.** When a `BgFactory` is set (`PueueBg`), a `BgWatcher` in `bg_command.rs` polls `pueue status --json` from the highest task id at job start and never reads command text. `shell_timing::ShellRecorder` runs the shared sanitiser (redact, strip hostile characters, redact, strip, cut) to `MAX_COMMAND_BYTES` or `MAX_SHELL_LOG_BYTES`, so a secret that straddles the cap is replaced whole. Records past `MAX_SHELL_COMMANDS` (256) are counted in `overflow`.
- **Kimi timing reads `wire.jsonl` after the agent exits.** `wire_timing::parse_wire` pairs `llm.request` with `usage.record` into `ApiWait` spans. The field names are unverified against a real Kimi capture and follow `tests/fixtures/kimi-wire.synthetic.jsonl`. A test that changes the shape must change the fixture too.
- **Timing tests inject the clock and the sink.** `otel_parse`, `wire_timing` and `telemetry` read no clock, and `TimingSink` is the seam that stands in for the server.

## Model allowlist

- **`model_allowlist` is a config-file list of exact model ids.** `resolve_model_allowlist` builds a `fleet_core::model_allowlist::ModelAllowlist`; an empty list or an invalid, duplicate or over-long entry stops startup. With the key unset every model passes at the box.
- **The box re-checks the model from the server blob.** `profile_apply::load_stamped` takes `config.model_allowlist` and returns `LoadError::ModelDenied` for a Profile model outside it. `floor::check_model` is the same check for a bare model name. The server checks the model at submit too (`FLEET_MODEL_ALLOWLIST`, ADR-0054).
- **Profile `tools` need the server stamp.** `floor::check_tools_stamp` refuses a Job that carries tools while `profile_tools_granted` is false. The wire default is false, so a missing stamp refuses.

## Askpass test

- **Own test file.** `tests/askpass_process.rs` runs the `fleetd askpass` binary, so it stays alone in its binary.

## Daemon test

- **Own test file.** `tests/daemon_jobs.rs` runs the whole daemon against a fake `FleetWorker` on a real socket, with a fake agent and fake `gh` scripts and a `file://` origin, so it stays alone in its binary.
- **The fake agent must leave a mark the test checks.** `claude_bin` is config, but a wrong path falls back to the real `claude` on `PATH`. The test asserts the committed file holds the fake's output.
- **Env is injected.** `run_with_env` takes the `FLEET_SERVER_URL` and `FLEET_TOKEN` lookup, so a test sets no process env.

## Credentials

- **A GitHub App job holds an installation token, not a PAT.** The holder accepts wire kind `github_installation_token` (stored as `CredentialKind::GithubApp`) only with shape `static_secret`, a value of `ghs_` plus letters, digits and `_`, and a `GitIdentity`. `JobCredentials::github` returns the PAT or that token, so push, `gh`, the mirror fetch and the broker read it the way they read the PAT. `JobCredentials::from_reply` also refuses a token with no `expires_at_ms`, so a token with no expiry fails at the first fetch and never reaches the refresh loop. It re-validates the identity with `fleet_core::credential::BotIdentity::new` and fails the job before the clone: `github app credential has no git identity` for a missing one, `github app git identity is invalid` for one outside the grammar. A reply that holds both a PAT and a token, a token twice, a `github_app` wire kind or an identity on a PAT is `credentials reply was invalid`. `expires_at_ms` is kept on the `Credential`. `CredentialBook::refresh_if_due` calls `GetJobCredentials` again when fewer than 10 minutes remain (exactly 10 is not due), before a Push or Gh child, with an injected `Clock`, and swaps the app token. The mirror fetch and the broker `gh` call resolve the token per call through `TokenSource` (refresh, then a `TokenLease` held until the child exits), never from a copy taken at job setup. `refresh_if_due_with` runs a hook before the new token is readable, and `AgentRunner::mask_refreshed` merges the new value into the job redactor entry in one update there (a job with no entry has ended and gets none), so no step reads an unmasked token; the redactor keeps masking the old one. Refreshes serialize per job through a lock held in the job's entry. A transient refresh failure (Unavailable, Expired, RateLimited) keeps the last good token until it expires and retries after 30 seconds. `RateLimited` is the per-User mint rate (`PRECONDITION_APP_MINT_RATE`): `CredentialBook::fetch` also waits it out `RATE_RETRIES` (7) times, `RATE_RETRY_DELAY` (10 seconds) apart, and fails the Job with `github app token rate limited` only if it persists; `with_rate_retry` is the test seam. A fresh token that already looks expired or inside the 10 minute window means the box clock runs ahead of the server's: the book takes it, marks the entry skewed, keeps it for `REFRESH_SKEW_MS` plus `REFRESH_SKEW_SLACK_MS` (50 minutes) after the fetch, fails the step with `credential expired` if the refresh still fails past that, and refreshes again only after `REFRESH_SKEW_MS` (45 minutes) by elapsed time, so a skewed clock spends one mint per interval. A clock that runs behind is not detectable. With a `Revoker` attached (`revoke.rs`, `Revoker::github()` in production; `Revoker::plain(addr)` exists only under `cfg(test)` and the `testing` feature, which fleetd's own dev-dependencies turn on), a swap revokes the replaced token and `CredentialBook::end` (the job end hook) revokes the held installation token, each on its own task, best effort, bounded by `REVOKE_TIMEOUT`. A push or `gh` child takes a `TokenLease` (`CredentialBook::lease_held`, which pairs the credentials with the lease) before it reads the token and holds it until it exits; the replaced token is revoked only once every lease on it has dropped, or after `DRAIN_LIMIT` (15 minutes), whichever is first. The job end revokes at once and never waits for a lease. `CredentialBook::fetch` ends any entry already held for the id, so it revokes that entry's token before it asks again. A failure logs `REVOKE_FAILED` only and never fails the job. A PAT job revokes nothing. A refresh that finds the job ended, or finds the entry replaced by a `fetch` for the same id (its turn lock is not the one the refresh holds; `store` compares them with `Arc::ptr_eq`), revokes the token it minted and stores nothing. A reply that fails validation (`AppIdentityMissing`, `AppIdentityInvalid`, `Malformed`) or whose swap `refreshed` refuses has its installation token revoked: `CredentialClient::fetch` hands the token values of the reply back in `Rejected`, and `fetch_checked` revokes them. `REQUEST_TIMEOUT` is `fleet_proto::CALL_BUDGET`, the same constant the server fits its mint budget under. the per-Job `PRECONDITION_APP_MINT_CAP`, `PRECONDITION_APP_INSTALLATION`, `PRECONDITION_APP_REPO`, a lease mismatch or a malformed reply fails the step with a fixed reason and never falls back to a PAT. The CI watch (`check_pr`, `poll_ci`, `failure_log`, `attach_log`) and `existing_pr` return that failure instead of reading it as a pending check or a missing pull request: `Watched::Failed` ends the job as failed with the reason.
- **The git identity env comes from `git_env` in `runner/token.rs`.** Every runner's agent env (claude, codex, kimi) and `Scope::Tree(job_id, path)` (the fallback commit) take it: the bot for an App job, else `JOB_NAME` and `JOB_EMAIL`. The job `.gitconfig` still holds the fixed identity and the env wins. A new git call path that commits takes it from `git_env` too.
- **The job redactor holds the token.** `adopt_credentials` merges every held value, so a `ghs_` token is masked in events, transcript lines and shell records. `JobCredentials::redactor` turns on `Redactor::with_installation_tokens` for an App job, which masks any `ghs_` run of 16 or more letters, digits and `_` by shape. The flag survives `clone` and `merged`, so every copy of the job redactor (the feed book, `ShellRecorder`, `workspace_for`, the broker wiring) masks a refreshed token it was cloned before. A PAT job keeps exact-match masking only. `fleet_core::validate`'s secret lint (`secret_like`) rejects `ghp_`, `ghs_` and `ghu_` text in a Profile.
- **The job path takes the GitHub token from the credential holder only.** With a `CredentialBook` attached, `GH_TOKEN` and `GH_ENTERPRISE_TOKEN` in `base_env` are dropped, a reply with no GitHub credential fails the job with `no github credential`, and the `gh` child env is the fixed set plus the holder token. The wiring refuses a plain `http` `FLEET_SERVER_URL` unless the host is loopback or `FLEETD_ALLOW_PLAINTEXT_CREDENTIALS=1`. Workspaces and the publish mirror are keyed by the Job `user_id` (ADR-0046).
- **The claude agent env takes its model secret from the holder too.** With a `CredentialBook` attached, `agent_spec` drops `CLAUDE_CODE_OAUTH_TOKEN` and `ANTHROPIC_API_KEY` from the base env and sets one from the held `anthropic_api_key` or `claude_subscription_token`; a claude job whose holder has neither fails with `no agent credential`. Judge jobs fetch no credentials and keep the base env. The value reaches the 0600 `env` file only, never `spec.json`.
- **A codex job's env is `codex::env` plus `git_env`.** `agent_spec` branches on `resolve(job.agent)`: a codex job gets the Codex argv, a per-job `CODEX_HOME` kept in the runner until `end_job`, and `CODEX_API_KEY` from the held `codex_api_key` as its one secret; with no held key the variable is absent, never a box value. An unknown agent fails with `agent is not supported` in `run_stream`.
- **A kimi job mirrors the codex job, and runs only on a disposable box.** `agent_spec` dispatches to `kimi_spec`: the argv `kimi -p <prompt> --output-format stream-json [-m <model>]` with `kimi_bin` from config, `kimi::env` plus `git_env`, an empty per-job `KIMI_CODE_HOME` kept until `end_job`, and `KIMI_MODEL_API_KEY` from the held `kimi_membership_key` or `kimi_platform_key`. A Profile model outside `kimi::resolve_model` fails with `kimi model is not valid`. `-p` runs under the auto policy with no approval (ADR-0043), so a kimi job on a box that is not disposable fails with `kimi needs a disposable box` before anything is built.
- **Dropped-subagent notes ride the first stream.** `queue_dropped_notes` holds them in `AgentRunner.notes` keyed by `carry_key`; the first `Stream::new` or resume takes them, and `end_job` and `clear_profile` forget notes nobody took. `Feed::queue_notes` takes at most `MAX_QUEUED_NOTES` (`MAX_DROPPED_NOTES` + 1, the extra slot is the summary note) and queues them as `phase` events behind the fetch events. An unparsed Kimi feed keeps its parser for notes.
- **A codex or kimi job's summary is empty by design.** `Feed::set_unparsed` runs in `Stream::new` for every job whose runner is not claude (judge jobs count as claude): the feed reads no line, and `finish` returns `complete = false`, `missing = ["parser"]` and no figure. Stats read those figures as `NULL` too (`fleet-server/src/stats.rs`). Remove both together when a parser lands: `has_output_parser` in `runner.rs` and the `NULL` handling in the stats `CASE` list.
- **Name the attacker uid in every secrecy claim.** A token is hidden from a process under another uid than fleetd's, never from the agent, which shares fleetd's uid (ADR-0024 Known limit). Write docs and doc comments to match.
- **Never run credentialed git or gh in a repo the agent wrote.** Linked worktrees share the common-dir config, so the agent can plant `core.sshCommand`, `credential.helper` or `url.*.insteadOf`. Finish fetches into a throwaway bare repo with no tokens, then pushes and opens the PR from it.
- **Credentialed children get a scratch `HOME`, `XDG_*` and `GH_CONFIG_DIR` in a scratch dir beside the job worktree, and only the one credential they need.** The agent can write that dir, so isolation relies on the process-group kill. The agent shares fleetd's uid, so it can still read the tokens through `/proc/<pid>/environ` and `/etc/swarm/secrets.env` (ADR-0024 Known limit). The push gets `GIT_ASKPASS` (the current fleetd executable), the `FLEETD_ASKPASS` marker that makes it answer as the helper, `FLEETD_ASKPASS_HOST` and the `GH_TOKEN` the helper prints. A credential reply names one host entry, the Job repository host. For a Forgejo entry, `FLEETD_ASKPASS_HOST` is that host and `GH_TOKEN` its token, and a `gh` child gets no Forgejo token. The helper answers a prompt only for that host: it refuses any userinfo other than `x-access-token`, a trailing dot, a port, a backslash and any non-ASCII byte. `gh` gets `GH_HOST` only when `token_host` is set. Without a credential holder the base env supplies `GH_TOKEN` only when `token_host` is set, and `GH_ENTERPRISE_TOKEN` only when that host is not `github.com`. Real `HOME`, `SSH_*`, `GIT_SSH*`, `GIT_EXEC_PATH`, `LD_*` and `DYLD_*` are never inherited. The push allows only `https` remotes on the `repo_hosts` list (`RepoPolicy`), so ssh, `git://` and `file://` remotes fail by design. Tests that serve a local bare repo build `RepoPolicy::new(Vec::<String>::new()).with_file_repos()` (or set `Config::allow_file_repos`) and never a config key.
- **Workspace git is cleared too.** `workspace.rs` runs every git call with `env_clear`, a scratch `HOME`, `GIT_CONFIG_GLOBAL=/dev/null` and `-c core.hooksPath=/dev/null -c core.fsmonitor=`. `tests/workspace_guards.rs` records each call with a fake git, so a new call path must go through `Workspace::git`.

## Agent config

- **`agent_config_dir` replaces the default `settings.json` allow list entirely.** An operator bundle that omits `Bash` leaves a `dontAsk` job unable to change files: `Edit`, `Write`, `NotebookEdit` and `MultiEdit` are denied by the argv floor, so edits go through Bash. An operator bundle can also drop the `Bash(curl *)` deny, because the bundle's `settings.json` replaces the default one.

## Fallback commit tests

- **Hostile repo.** The fallback runs git in an agent-written tree. Tests plant hooks, `filter.<name>` config and `core.fsmonitor` and assert none ran. Read `git config --list --name-only` before the first git call that touches the tree, or a clean filter runs during `status`.
- **Fake `claude` modes.** The prompt carries `mode:path` as in the spawn tests; `write`, `commit`, `secret` and `trap` cover the fallback cases.

## Config keys

- **`Config::resolve` sits at the clippy `too_many_lines` cap.** Put a new key's env, file and validation logic in a helper fn and call it once, or clippy fails the build.
- **Binding a `tokio::net::UnixListener` needs a runtime.** A plain `#[test]` that calls `bind_socket` or `bind_hook_socket` panics with "no reactor running"; use `#[tokio::test]`.

## Named pipes and modes

- **No `mknodat` on macOS, no `unsafe` allowed.** `jobenv::create_stdout_fifo` runs the `mkfifo` program. A nonblocking FIFO reader reads 0 until a writer opens, then `WouldBlock`, so a test opens the writer before it asserts idle. A read after the writer opened can still return `WouldBlock` under load: `the_fifo_is_0660_carries_the_group_and_streams_to_a_reader` failed with Os code 35 in two full verifies and passed in 5 and 6 isolated reruns. Retry on `WouldBlock` with a bounded wait in the test helper.
- **Mode asserts need the umask in mind.** `create_dir_all` and git leave 0755 dirs, so assert group-write and setgid bits (`& 0o2020`), not group-read.

## Systemd launcher test

- **Own test file.** `tests/systemd_launcher.rs` runs a fake `systemctl` script and the `fleetd agent-exec` binary, so it stays alone in its binary. The script is written once in a `OnceLock<TempDir>`, and its per-job state lives in a directory named after the job id, so every test uses a unique id.
- **Startup sweep.** `sweep_stale_runs(config, run_dir)` takes the run root as a parameter and only acts for the systemd launcher. `run_with_hub` calls it only after `bind_all` succeeds, so a second instance that fails to bind sweeps nothing. It removes real directories with a job-id name through `RunDir` and skips `hook`, symlinks and files. Unit states: a unit in any state except `inactive` and `failed` (`is_live`, so `activating` and `deactivating` too) is stopped, then reset-failed; a `failed` unit is reset-failed; an inactive unit gets no call. Tests plant dirs in a temp run root.
- **Run dir contract.** With `agent_launcher = "systemd"`, `systemd.rs` makes `<run_dir>/<job id>/` (default `/run/fleet`), mode 0750 with `job_group`, holding `env` (0600, the `EnvironmentFile`), `spec.json` (`id`, `argv` and `cwd`, plus `telemetry_port` and `host_netns` when telemetry is on, 0640 with the job group) and `stdout` (a FIFO, 0660). It runs `systemctl start --no-block fleet-agent@<id>.service`, polls `show`, and at the end calls `stop` and `reset-failed` and removes the dir. `deploy/README.md` holds the operator view.
- **Environment values live in `envd.rs`.** `ReleasedEnvironment::from_reply` holds each secret in `Zeroizing` and wipes on drop. `redaction_with_limit` registers every value in full and the 8-byte-or-longer lines of multi-line values only, capped at `MAX_REDACT_LINES` (4096), and a single-line value does not count against the cap. Nothing registers `$FLEET_ENV_OUT` file lines yet (ADR-0067 decision 9). The setup unit sweeps (`sweep_setup_root`, `sweep_trees`) take a `live` predicate, and the startup sweep in `runtime.rs` passes `|_| false`, so only the `sweep_trees` tests exercise the live-keep path.
- **Telemetry env.** `select_launcher` calls `with_telemetry` only after `config.require_host_netns()` succeeds. `launch` starts capture first, calls `TelemetryEnv::apply` on the spec env, then renders the env file, so the bearer reaches only the 0600 env file. Only a spec with `otel` set (claude, not judge) gets capture. A token byte outside `[A-Za-z0-9_-]` starts none.
- **Job socket.** `select_launcher(config, gid, services)` gives the systemd launcher a `JobSocketSetup`, and `launch` binds `<run_dir>/<id>/job.sock` after the FIFO and before `start`. The poller closes it right after the unit ends, before `stop`, and `Drop` closes it first, so it is unlinked before the dir is removed on every path. The direct launcher makes none and logs `JOB_SOCKET_REFUSED` once when services are given. The fake `systemctl` appends `<verb> sock|nosock` to `seen` when the case wrote a `rundir` file, so a test can assert the socket state at each call.
- **The fake is injected as `systemctl_path`.** No env var selects it. `show.N` files give the Nth `show` reply and `show.last` the rest.

## Linux uid test

- **Own test file, opt-in.** `tests/linux_uid.rs` builds an image (`tests/linux_uid/Dockerfile`) with `fleetd` (986, in `fleet-work` 987) and `fleet-job` (985), compiles itself and `fleetd` inside it, and runs the container tests as uid 986. The real `AgentRunner` and `SystemdLauncher` start a fake agent through `tests/linux_uid/systemctl`, which drops to 985:987 with `sudo -n setpriv` and runs `fleetd agent-exec`. Run it with `mise run it:linux`; it needs docker or colima, and the in-container build needs network access to crates.io.
- **`container_suite_passes` is `#[ignore]`.** It needs docker, so nextest and `cargo test` skip it and `clippy --all-targets` still compiles it. With no usable `docker info` it prints `SKIP: docker not available, run mise run it:linux with docker or colima` and passes.
- **Marker guard.** The container tests return early with a skip message unless `/etc/fleet-it` exists, so a plain `cargo test` on a laptop runs none of them.
- **The shim's env parse is a shell loop, not systemd's.** It strips one pair of quotes per line and does not undo the `\\` and `\"` escapes of `render_env_file`; a test value holding either needs the agent to record the variable itself.
- **The caches are the named volumes `fleet-it-target` and `fleet-it-cargo`.** Remove them to force a cold build.
