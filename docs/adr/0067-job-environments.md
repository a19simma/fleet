# Job environments

Status: Proposed 2026-11-09. Built: the sealed store and the `FleetEnvironments` RPCs, release by `GetJobEnvironment`, submit, batch and CI retry pins with default bindings, the CLI and web pages, the fleetd holder, Delivery files, redaction and startup sweep, and the systemd Setup launcher with the `fleetd env-setup-exec` shim. Not built: `egress_private_allow` (no code reads the key), registration of `$FLEET_ENV_OUT` file lines with the Redactor, the carry of `out/` to the agent, and Providers. Unverified: every sandbox claim of the Setup unit, because the live probe `deploy/probe-env-setup.sh` has not been run, so this ADR is not marked built. Builds on ADR-0035, ADR-0036, ADR-0040, ADR-0043 and ADR-0054. Amends ADR-0033, ADR-0038, ADR-0055, ADR-0031, ADR-0036, ADR-0054 and ADR-0040. Reserves ADR-0068.

A Job often needs a secret the agent profile cannot hold: a Proxmox token, a kubeconfig, a registry login. Credentials (ADR-0040, ADR-0043) are a closed set of agent and forge kinds, and ADR-0033 promises the agent never sees them. A Profile is shareable and holds no secrets (ADR-0034). This ADR adds a third object, the **Environment**: a named, versioned bundle of sealed secrets and optional setup scripts that a User attaches to a Job.

## Decision

1. **Per-User and private.** An **Environment** belongs to one **User**. There is no sharing, no visibility level and no Catalog entry. Profiles have sharing (ADR-0052). Environments never do. Every read and write scopes by `user_id`, and a foreign name gets the same `NOT_FOUND` reply as an unknown name.
2. **Version stream.** An **Environment version** holds structure: an ordered list of entry specs plus declared egress hosts. Structure is immutable and identified by `(environment id, version number)` and a content hash. The hash is a domain-separated, length-prefixed binary SHA-256 over host list, secret specs (sorted by case-folded name) and scripts (in execution order). It covers no secret value and no value fingerprint. An **Environment secret** value is mutable and sits outside the version. A Job pins `(environment id, version)` and gets the secret values current at release. A pin freezes scripts, hosts and secret names, and does not freeze values, so a rotation needs no resubmit. The insert-only `environment_use` table records the fingerprint of each value released, so an audit tells which value a Job saw. A structural change that yields the latest hash writes no new version.
3. **Two entry kinds.** Entries are secrets and **Environment scripts**. They share one name grammar (ASCII `[A-Za-z_][A-Za-z0-9_]{0,63}`, unique after case fold), one namespace per version and one set of limits: at most 64 entries, 8 to 65536 bytes per secret value, 1 to 65536 bytes per script body, 786432 bytes for script bodies plus current secret values, at most 16 declared egress hosts. The total cap sits below the 1 MiB decode limit of ADR-0018 so a reply with names and framing fits. A secret value is UTF-8, has no NUL, is not blank or one repeated character, and holds no character the hostile-text reject set refuses (ADR-0063) except `\n` and `\t`. The minimum equals `redact::MIN_SECRET_LEN`, so every stored value is one the Redactor can mask. A script body starts with a `#!/` line so fleetd never guesses an interpreter. A multi-line value is refused for env delivery. Reserved entry names, matched after case fold, are `telemetry`, `PATH`, `HOME`, `HTTPS_PROXY`, `FLEET_*`, `LD_*`, `GH_TOKEN`, `GITHUB_TOKEN`, `ANTHROPIC_*`, `CLAUDE_*`, plus `OTEL_*`, `DYLD_*`, `HTTP_PROXY`, `NO_PROXY`, `ALL_PROXY`, `GIT_*`, `GH_*`, `SSH_*`, `XDG_*`, `TMPDIR`, `SHELL`, `USER`, `LOGNAME`, `PWD`, `OLDPWD`, `IFS`, `BASH_ENV`, `ENV` and `MISE_*`. Each addition has a reason in the ENV-1 task; ENV-1 may drop one.
4. **Capability for scripts.** A secrets-only version is open to every User. A version with a script needs the admin capability `env:scripts` (ADR-0054 list). The server checks it live under `FOR SHARE` on the capability row at save, at submit and at release. A revoke between submit and lease refuses the Job at release with the fixed denial of decision 7.
5. **Delivery.** The default is a **Delivery file**: one file per secret under `/run/fleet/<job id>/envd/`, directory 0700 and files 0400, owner `fleet-job`, no trailing newline added. A secret may choose env delivery instead, written to `envd.env` for an `EnvironmentFile=` of the agent unit. **Agent-visible** is a per-entry flag and defaults to false. A secret with `agent_visible = false` exists only in the Setup unit input root and never enters `envd/` or `envd.env`. Env delivery is refused for a secret that is not agent-visible, since no consumer reads it. fleetd registers every value with the Job Redactor before it writes any file.
6. **Setup unit.** Scripts run in `fleet-env@<job id>.service`, a **Setup unit** modelled on `fleet-tool-install@.service`, before the agent starts. It runs as `fleet-job`, with `PrivateNetwork=yes`, an empty capability set, `ProtectSystem=strict`, `ProtectProc=invisible` and `NoNewPrivileges=yes`. Its input root is `/run/fleet-env/<job id>/`, separate from `/run/fleet/<job id>` because the agent unit mounts all of the latter. One writable bind, `$FLEET_ENV_OUT`, carries script products to `envd/out/`. Egress goes through the Egress proxy and reaches only the hosts the version declares intersected with the Box `egress_allow` ceiling. An Environment cannot widen the ceiling. A version with scripts and no declared host gets no network. The proxy keeps `CONNECT host:443` only and keeps refusing private ranges. An operator can open private endpoints with a Box config key `egress_private_allow`, a list of exact `host:port` pairs applied to the Setup phase only. Each pair must also appear in `egress_allow`, and the resolve-then-check dial stays. No Profile or Environment can set it, and the agent phase never gets it. Each step has `on_fail`: `Abort` (default) fails the Job before the agent starts, with phase `SETUP`, a fixed error and the step name. `Continue` records a Job note and runs the next step. The total budget (sum of step timeouts, at most 1200 s, each step 1 to 600 s) is a hard stop. A step cut by it skips the rest, and the Job fails if a skipped step was `Abort`. Step output is capped at 64 KiB per step, read with `take(cap + 1)`, redacted and stripped (ADR-0063), then added to Job notes.
7. **Release and lifecycle.** A new `FleetWorker.GetJobEnvironment{job_id, attempt, box}` call carries the same lease authorisation as `GetJobCredentials`. A wrong Box, a wrong attempt, a Job not RUNNING, an expired lease, an unknown Job and a revoked `env:scripts` all give `PERMISSION_DENIED` with one fixed message. A RUNNING Job with no pin gets an empty reply. The server writes the `environment_use` rows in the transaction that reads, before the reply, and a failed insert fails the call. The claim reply carries `has_environment`, so a Job with no pin makes no call. Nothing persists between Jobs: no daemon, no VPN session, no cache. The Job end hook (`JobEnd::on_end`, `crates/fleetd/src/runner.rs:737`) stops the Setup unit, shreds the delivery tree and drops the value map on every end path. A startup sweep removes every `envd` and `/run/fleet-env/<id>` tree whose Job is not live, by rename-aside then delete, and stops a leftover `fleet-env@*` unit. A restart ends every Job (ADR-0036), so every tree present at startup is dead.
8. **Setup time is Overhead.** ADR-0055 defines Overhead as wall time outside the agent window. Setup ends before the agent window opens, so its time lands in Overhead. There is no sixth timing part and no new proto field. Job notes carry per-step durations as text.
9. **Redaction is best effort.** fleetd registers each secret value in full, each line of 8 or more bytes of each value, and each line of 8 or more bytes of each file under `$FLEET_ENV_OUT` once the Setup unit ends. At most 4096 lines taken from multi-line values are registered (`MAX_REDACT_LINES`, `crates/fleetd/src/envd.rs:55`, counted in `redaction_with_limit`). A single-line value is registered in full and does not count against the cap. Beyond the cap the longest lines are kept first, and a Job note says `redaction coverage reduced`. Registration of `$FLEET_ENV_OUT` file lines is not built: `ReleasedEnvironment::redaction` reads held values only. The order of ADR-0063 (redact, strip, redact, strip, cut) is unchanged. Masking applies to transcript chunks, job events and telemetry, shell command records and logs, Setup output in Job notes, CI logs, and the PR title, PR body and commit text fleetd writes. The server applies none: it stores what fleetd sent. Limits, stated plainly:
   - Match is exact. Base64, URL-encoded, hex, split, reversed or compressed forms are not caught.
   - Lines under 8 bytes are not registered.
   - A secret the agent copies into a worktree file and commits is pushed. fleetd does not scan diffs.
   - Anything the agent sends over `fleetd fetch` or another channel leaves unmasked. ADR-0038 already records the allow-all fetch exfiltration path. An agent-visible secret is visible to the agent and the agent can leak it. `agent_visible = false` is the only barrier.
   - A value a script derives is covered only when it lands in a file under `$FLEET_ENV_OUT`.
10. **Profile never carries an Environment.** No Profile field names one, and `deny_unknown_fields` (ADR-0034) refuses an `environment` key. A User binds an Environment as a default to a repository key (ADR-0059) or to a **Profile identity** (ADR-0057) in an `environment_default` row, outside the Profile content, so the Profile hash does not change. At submit the server picks, in order: the explicit `environment` field, the repo binding, the profile binding, none. Repo wins over profile because a repository needs a particular cluster or token more often than a Profile does. `--no-env` sends `-`, which no Environment name can be. A binding to an Environment with scripts, for a User who lost `env:scripts`, makes submit refuse and never drops the scripts. Deleting an Environment removes its bindings.
11. **One Environment per Job.** Judge Jobs get none. A CI retry (ADR-0028) does not resolve again: it inherits the parent pin through `environments::pin_inheritable` (`crates/fleet-server/src/store/ci_retry.rs:75`, `crates/fleet-server/src/environments.rs:387`), which reads the pinned version and re-checks `env:scripts`. A deleted Environment or a revoked capability stores `ci_retry = env_unavailable` and submits no fix Job. A batch with a named Environment resolves it once through `resolve_pin` and pins every child to that version, and `-` pins none. A batch with no `environment` field resolves each child's default with `resolve_pin_with_defaults`, the repository binding for all children and else the binding of the child's own Profile, so children of one batch can hold different pins (`crates/fleet-server/src/batches.rs:273-300`). A replay under the same idempotency key compares the stored pin with the request. A named request compares the name and the version that is latest now (`pin_matches`, `crates/fleet-server/src/environments.rs:415`), so editing or deleting the Environment between two submits under one key makes the resubmit a conflict. A default request compares against what the bindings resolve to now (`default_pin_matches`, `crates/fleet-server/src/store.rs:865`), and a refused resolution counts as a mismatch.
12. **Providers: term and reserved numbers only.** A **Provider** is a named, operator-enabled network or identity helper that a Setup unit may use. Netbird is the only candidate. v1 has no Provider type and uses no wire field for one. `GetJobEnvironmentReply` reserves field numbers 7 to 9 for providers, and this ADR reserves ADR number 0068 for the provider ADR. ADR-0068 is not written here. Its decisions (mode, key custody, operator opt-in key, namespace wiring) depend on a live spike, and a Proposed ADR before it would record guesses. Research in `docs/phase0/netbird-provider-research.md` section 2.6, which marks it inferred and unverified, infers that `JoinsNamespaceOf=` with `PrivateNetwork=yes` cannot both carry the netbird tunnel and exclude the agent: a shared private namespace holds loopback only, so a client inside it reaches no management server, relay or peer, and a client in the host namespace puts its SOCKS5 listener on host loopback where any unit sharing that namespace can use it. A VPN path also bypasses `egress_allow` and the Egress proxy, which is the policy of ADR-0038, so adoption is a security decision. Any provider needs an operator opt-in key in Box config that no Profile or Environment can set. If netbird is dropped, 0068 is released and the reserved field numbers stay.

## Storage and sealing

- Tables: `environment`, `environment_version` (immutable by trigger, survives an Environment delete so a pinned Job still resolves), `environment_entry` (script bodies in plaintext: scripts are hashed and reviewable, and hold no secret), `environment_secret`, the insert-only `environment_use` (no foreign key, as `credential_use`), and two nullable `jobs` columns `environment_id` and `environment_version` with a both-or-neither CHECK.
- `environment_secret` reuses the `Sealer`, the key ring, the master key file and the fingerprint function of ADR-0040. It adds an AAD constructor with a fixed prefix label, so a credential ciphertext cannot open as an Environment secret and the reverse. A rename is delete plus put, because the name binds the AAD. The unbuilt re-seal pass of ADR-0040 covers this table once built.
- `fleet-core` holds the types as fallible constructors with private fields (`EnvironmentSpec::new` checks every cross-entry rule once) and the limits as shared constants that `fleet-proto` re-exports.
- Decode limit: the server decodes `FleetWorker` requests up to `MAX_MESSAGE_BYTES`, 1 MiB (`crates/fleet-server/src/service.rs:173`, `:1155`), and encodes its replies up to `MAX_PROFILE_MESSAGE_BYTES` (`:1156`). The `GetJobEnvironment` request is three short fields and the reply is capped at `MAX_JOB_ENVIRONMENT_REPLY_BYTES`, 768 KiB of values plus 64 KiB of framing, checked against the encoded length before the audit rows commit, so no limit is raised and ADR-0018 is not amended (`crates/fleet-server/src/environments.rs:1312` returns `TooLarge` over the cap before the `environment_use` rows are written). A later change that raises a limit amends ADR-0018 in the same commit. The fleetd client sets its decode limit explicitly, as the credential client does (`crates/fleetd/src/cred/mod.rs:536`).
- The client RPCs sit in a new `FleetEnvironments` service. The caller must be a User. The static client token and the Box token get `PERMISSION_DENIED`. No RPC returns a secret value.

## Accepted risk: shared Box token

The risk of ADR-0033 applies. A holder of the shared Box token that names the right Box and attempt reads the Job owner's Environment secrets. The fix is per-Box tokens, as in ADR-0033.

## Verification state

Inferred, not part of the design: each item below is unverified until a live probe or test records it.

- `/run` is tmpfs on target Boxes. ENV-5b asserts the `statfs` type at runtime and refuses a non-tmpfs mount.
- The quoting `EnvironmentFile=` accepts for a value. ENV-5b reads systemd.exec(5) and round-trips through the real parse on a live host.
- Two concurrent Jobs under the one `fleet-job` uid. ADR-0031 did not probe it. Concurrency is 1 today, and the Delivery file is readable by the agent uid.
- How the Egress proxy reaches a Setup unit that holds only `lo`. ENV-6a reads the `agent-exec` shim and reuses it, and stops and reports if it cannot.
- Each sandbox directive of the Setup unit, on a live host, one probe per directive with a positive control. `deploy/probe-env-setup.sh` is written and has not been run (`deploy/README.md`, Setup unit probe). Until its output from a live Box is recorded, the sandbox claims of decision 6 stay unverified here and the status of this ADR does not become built.
- `Redactor::redact_str` cost with 4096 registered entries. ENV-5a measures it.

## Consequences

- A User can give a Job a kubeconfig or a minted token without a Credential kind and without a Profile change.
- The default `agent_visible = false` fails closed: a secrets-only Environment of setup-only secrets does nothing until the User opts in with `--agent`, and the CLI and web warn. A mistake shows as a failed Job and not as a silent leak.
- Scripts run code with the User's secrets before the Floor and the permission mode apply. The `env:scripts` capability gives an operator the lever.
- Private endpoints (a Proxmox API on a LAN address, a private Kubernetes API) work only through `egress_private_allow` or a future Provider.
- A pin does not freeze secret values. A rotated value reaches the next release of a queued Job.

## Considered and rejected

- **Environment secrets as `credentials` rows with a new kind.** Kinds are a closed, forge-and-agent shaped set (ADR-0043), the AAD binds `kind`, and the release path promises the agent never sees the values (ADR-0033). Mixing breaks that promise.
- **Environment fields inside the Profile.** A Profile is shareable and hashed into every Job. Sealed secrets cannot ride in it, and a name inside would leak the Environment to every reader of a shared Profile.
- **Env-var-only delivery.** Values show in `/proc/<pid>/environ`, in `env` dumps that land in transcripts and in child processes.
- **Scripts open to all Users.** Code runs with the User's secrets before the Floor applies. A capability gives an operator a lever.
- **Mutable scripts.** A Job's behaviour would change under its pin and the hash would mean nothing.
- **Scripts as a fleetd child.** It would inherit the fleetd uid and its view of `/etc/swarm`.
- **Scripts inside the agent unit.** The agent shares the cgroup and sandbox of the script, and setup-only secrets could not be withheld.
- **Setup-only secrets under `/run/fleet/<id>`.** The agent unit mounts that whole directory.
- **KMS or per-secret keys now.** Same trade-off as ADR-0040: an availability dependency on the claim path.
- **A persistent per-User Environment (a VM or container that survives).** Lifecycle per Job is simpler to clean up and has no cross-Job leak surface.
- **All `egress_allow` hosts in the Setup unit with no declared hosts.** A reviewer cannot judge a script's reach.
- **`agent_visible` default true.** A User who forgets the flag exposes a token that only a script needed, to an agent that can leak it.
- **Refuse private addresses with no operator opt-in.** The stated use cases need them, and the only other route is an unbuilt Provider.
- **Per-port allow on public hosts only.** It does not help LAN endpoints.
- **Profile binding over repo binding, or refuse when both differ.** The first hides the specific fact behind the general one. The second adds friction for a rare case.
- **A CI retry that inherits nothing.** A retry whose tests need the kubeconfig would fail. A judge inheriting would run the Owner's secrets for no reason.
- **Decide on netbird now (spike first, ADR-0068 written after research).** The inference in decision 12, unverified until a live spike, voids the plan to join a namespace. Only the research is recorded.
