# T1. Does Stop fire at the end of claude -p?

Result: Pass.

## Question

Does the `Stop` hook fire at the end of `claude -p`, and what do the JSON and stream-json outputs look like? From plan.md, Phase 0 test T1.

## Setup

Box: <box>, Claude Code 2.1.289, subscription auth (CLAUDE_CODE_OAUTH_TOKEN). `ANTHROPIC_API_KEY` was checked unset before every run (the run script aborts with exit 99 if set). No secret value was printed.

Per-test artifacts on <box> under `~/phase0/T1/`:

- `settings.json`: command hooks for Stop, SessionEnd, Notification, UserPromptSubmit. Each runs `cat > ~/phase0/T1/hooklog/<Event>-$(date +%s%N).json`. Passed with `claude --settings`, ~/.claude/settings.json untouched.
- `run.sh <label> <args>`: sources box.env and secrets.env, checks the API key is unset, runs `claude -p --settings ~/phase0/T1/settings.json <args>` in `~/phase0/T1/wd`, prints exit code and wall time.
- Hook logs per run: `hooklog_a1` .. `hooklog_a4`, `hooklog_interactive`. Outputs: `a1.out` .. `a4.out`.

## Commands and results

Run a1: `./run.sh a1 "reply with ok" --output-format json` (no `--bare`). Exit 0, 3.0 s wall. Result JSON has `result:"ok"`, `total_cost_usd:0.129524` (first call, cache creation of 32370 tokens), `session_id`, `usage`, `num_turns:1`, `duration_ms:2015`, `is_error:false`, `terminal_reason:"completed"`.

Hook files written, in order (nanosecond stamps):

```
UserPromptSubmit-1792836780615277183.json
Stop-1792836782609033644.json
SessionEnd-1792836782624704997.json
```

Stop to SessionEnd gap: 15.7 ms. UserPromptSubmit to Stop: about 2.0 s. Notification did not fire (expected, no permission prompt in `-p`).

Run a2: `./run.sh a2 "reply with ok" --output-format stream-json` (no `--verbose`). Exit 1, 0.45 s. stderr, verbatim:

```
Error: When using --print, --output-format=stream-json requires --verbose
```

So `--verbose` is mandatory with stream-json in `-p`. Hooks logged for this failed run: only `SessionEnd-1792836789929849497.json` (no UserPromptSubmit, no Stop, and its key set lacks `prompt_id`).

Run a3: `./run.sh a3 "reply with ok" --output-format stream-json --verbose`. Exit 0, 2.1 s. Line types, in order: `system system system assistant rate_limit_event result`. Last line is a `result` message:

```
{"type":"result","total_cost_usd":0.006518,"session_id":"1862cc35-...","usage":true,"num_turns":1,"duration_ms":1737,"is_error":false}
```

All six asked-for fields present (`usage` present as an object). Hooks: UserPromptSubmit, Stop, SessionEnd, same order as a1.

Run a4 (tool call): `./run.sh a4 "run the bash command: echo hi, then reply with done" --output-format json --allowedTools Bash`. Exit 0, 10.5 s, `num_turns:2`, `result:"done"`, `total_cost_usd:0.1417836`. Hooks:

```
UserPromptSubmit-1792836792521430598.json   (the real prompt)
UserPromptSubmit-1792836801315581652.json   (synthetic, see below)
Stop-1792836802521288143.json               (last_assistant_message "done", reason null)
SessionEnd-1792836802551578761.json
```

There was exactly one Stop for the whole run, not one per tool turn.

Surprising: the second UserPromptSubmit has the same `session_id` and `prompt_id` as the first, and its `prompt` field is a harness-generated block beginning `<agent-message from="a7c3e16ae013bdcd5">` `[Subagent hand-back] ...`. On the box, the Bash tool call was delegated to a subagent (the runner agent from the baked global config), and its hand-back is injected as a pseudo user prompt that fires UserPromptSubmit. A consumer that treats every UserPromptSubmit as a human prompt will log a bogus one. Key sets of both are identical.

Interactive session (tmux session p0t2, dir `~/phase0/T1/wd`, `--permission-mode default`): two prompts that needed Write permission each produced UserPromptSubmit, then (after approval) Stop. See T2.md for the Notification file. Files in `hooklog_interactive/`.

## Result

Pass. `Stop` fires once at the end of `claude -p` (json and stream-json), followed about 16 ms later by `SessionEnd`. The `result` message (last line of stream-json, the only object of `--output-format json`) carries `total_cost_usd`, `session_id`, `usage`, `num_turns`, `duration_ms`, `is_error`. Without `--verbose`, stream-json fails with exit 1 and no output.

## Plan impact

- Event table keeps `Stop` as the turn-complete signal for `claude -p`. No change.
- Document that `Stop` fires once per `-p` run even with tool calls, and that `SessionEnd` follows within tens of ms (reason `other` for `-p`).
- fleet-job must pass `--verbose` whenever it uses `stream-json` (decision 8 follow-up). `--output-format json` needs no flag.
- fleetd's UserPromptSubmit handler must tolerate synthetic prompts from subagent hand-back (prompt starts with `<agent-message from=`). Same `prompt_id` as the real prompt. Mark or drop these in the normalizer so they do not show as human prompts.
- A failed `-p` start still emits `SessionEnd` with no `prompt_id`. fleetd should not assume `prompt_id` exists on SessionEnd.
