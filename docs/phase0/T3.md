# T3. Do http hooks accept a unix-socket URL?

Result: Fail for unix sockets. Pass for loopback http. http hooks work on 2.1.289.

## Question

Does Claude Code's `type: "http"` hook accept a unix-socket URL, and do http hooks work at all on 2.1.289 (the docs say `onFailure` needs 2.1.295 or later)?

## Setup

Box: <box>, Claude Code 2.1.289, subscription auth. `ANTHROPIC_API_KEY` checked unset before each run.

Artifacts under `~/phase0/T3/` on <box>:

- `listen.py`: throwaway python listener on the unix socket `~/phase0/T3/hook.sock` and on `127.0.0.1:18765`. Writes each raw request (headers and body) to `log/<tcp|unix>-<ns>.txt` and answers `200 {}`. Self-check with `curl` to both listeners worked before the tests. Stopped after the tests.
- `s_tcp.json`, `s_unix1.json`, `s_unix2.json`, `s_tcp_onfail.json`: one http Stop hook each. `run.sh <label>` runs `claude -p --settings ~/phase0/T3/<label>.json --debug-file <label>.debug "reply with ok" --output-format json` in `~/phase0/T3/wd`.
- Per-run request captures in `log_<label>/`, debug logs `<label>.debug`.

## Findings on 2.1.289

- `type: "http"` hooks work. The version-gate concern does not apply to the type itself.
- Unix-socket URLs (`unix:` and `http+unix:`) are rejected by the client with `Unsupported protocol`. The hook errors are non-blocking: the `claude -p` run still exited 0 with `result` "ok".
- The unknown/new field `onFailure: "block"` was accepted without any warning on stderr or in the debug log, and the hook still ran and succeeded. On a success path it has no visible effect, so whether 2.1.289 ignores it silently or implements it is unproven here. T8 tests it on a failing hook.
- Only the Stop event was tested in T3.

## Plan impact

- The plan already keeps the loopback port as the hook path and the socket for `fleet-job`. Confirmed. State in the plan that unix URLs are rejected on 2.1.289, so there is no socket option for hooks on this pin.
- http hooks are usable on the pinned version. No need for a curl command-hook stand-in.
- Do not rely on `onFailure` until the pin is at or above 2.1.295 (see T8 for observed behaviour).
- fleetd's hook endpoint routes on URL path (`/hook/<Event>`); there is no event header.
