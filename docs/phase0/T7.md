# T7: bearer token rejected and accepted over gRPC

Date: 2026-10-24. Box: <box>. Result: Pass.

## Question

From plan.md Phase 0, T7: does a gRPC server that requires `authorization: Bearer <token>` answer UNAUTHENTICATED to a wrong token and to no token, and succeed with the right token? Can user `agent` read the token from a 0640 `root:agent` file while another user cannot? Does redaction (ADR-0012) remove the token from an event? ADR-0014 defines the wire form and the file mode.

## Deviation from the plan

FLEET_TOKEN does not exist in /etc/swarm/secrets.env yet, and /etc/swarm was not modified. A throwaway file stood in: /tmp/phase0-t7/secrets.env, `FLEET_TOKEN=<32 random hex>`, created with sudo, owner root:agent, mode 0640. The token was never printed. Length 32. The directory and file are deleted. Scripts stay in ~/phase0/T7 on <box>.

The server ran plain on 127.0.0.1:50999, so the call crossed loopback and not a VPN. No TLS.

## Setup

- python3 is a mise shim, `Python 3.14.7`.
- `python3 -m venv ~/phase0/T7/venv`, then `pip install grpcio grpcio-tools` (1.84.1), plus `grpcio-reflection` 1.84.1 for grpcurl reflection. Run as pueue job 1 via `pueue start 1` because job 0 from another runner held the single slot and queued it.
- `python -m grpc_tools.protoc -I. --python_out=. --grpc_python_out=. fleet.proto`
- Proto: `service FleetIngest { rpc Ping(PingRequest) returns (PingReply); }`.
- server.py: a `grpc.ServerInterceptor` reads the `authorization` metadata value, compares it with `"Bearer " + token` using `hmac.compare_digest`, and on mismatch returns a handler that aborts with UNAUTHENTICATED.
- grpcurl 1.9.4 installed with `mise use -g github:fullstorydev/grpcurl`. This edited the global mise config on <box> (~/.config/mise/config.toml).

## Calls

Python client (key `authorization`, lowercase), then grpcurl with `-proto fleet.proto`:

| Call | Python client | grpcurl |
|---|---|---|
| no token | UNAUTHENTICATED bad token | Code: Unauthenticated, Message: bad token |
| wrong token | UNAUTHENTICATED bad token | Code: Unauthenticated, Message: bad token |
| right token read from the file as agent | OK pong <box> | `{"msg": "pong <box>"}` |

grpcurl with `-H "Authorization: Bearer ..."` (capitalised key) also succeeded: grpcurl lowercases the key, as HTTP/2 requires. The lowercase `authorization` form is the one tonic's `MetadataKey` needs, and the interceptor matched it.

## Redaction

redact.py loads every value from secrets.env, sorts by length descending, and replaces each occurrence with `[REDACTED]` while walking the JSON (keys, strings, lists, objects). Test event held the token twice: inside a shell command string and inside a nested list string.

```
before: 2   (grep -o count of the token)
after:  0
{"type": "tool_use", "cmd": "curl -H 'authorization: Bearer [REDACTED]' x", "nested": {"l": ["a [REDACTED] b"]}}
```

## Cleanup

Server killed by pid file (`kill $(cat server.pid)`); a later client call returned UNAVAILABLE. /tmp/phase0-t7 removed with sudo. Intermediate event files removed.

## Plan impact

- Auth interceptor works as ADR-0014 specifies. Constant-time compare on the full `Bearer <token>` string is enough. The server must gate every service, not only the ingest methods.
- gRPC server reflection sits behind the same interceptor here: grpcurl without a token fails at reflection with Unauthenticated. If the real server enables reflection, decide whether it is public. Behind the interceptor it leaks nothing.
- Secrets file at 0640 root:agent works for fleetd running as agent. Any other user is denied. This confirms the 0640 `root:agent` secrets-file pattern for FLEET_TOKEN.
- The throwaway file's directory was root-owned, so agent could not write a pid file there. Unrelated to production, but fleetd's own state paths must not sit in /etc/swarm.
- Redaction by exact value substring works on nested JSON. Limits: it does not catch encoded forms (base64, URL-encoded, split across two fields). Redact before serialising, and sort values longest first so a short value cannot break a longer one. A token under a few characters would over-redact, so fleetd should skip very short values.
- grpcio gotchas: reflection needs the separate `grpcio-reflection` package. Metadata keys must be lowercase. Tonic's `MetadataValue` for `Bearer <token>` must parse as ASCII with no newline.
- Not covered: TLS, tonic as the client (a Rust client was not run; only the lowercase wire form was checked with grpcio and grpcurl), and a real VPN path.
